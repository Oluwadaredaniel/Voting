Anti-Cheat & Integrity

How the system prevents fraud — including by you, the organiser.

⚠️ What the admin cannot do

🚫
Cannot vote multiple times. Your school email is subject to the same MongoDB unique index as every other voter. A second vote in any category is rejected at the database level — not just the UI.
🚫
Cannot forge votes for other students. Every vote is tied to a Firebase-verified UID. The server checks the token on every request — there's no way to submit a vote as someone else through this app.
🚫
Cannot delete or edit votes. The Express API has no DELETE or UPDATE route for votes. The only write operation is INSERT, and the unique index makes that idempotent per category.
🚫
Cannot see live results during voting without this passcode. The results endpoint requires the x-admin-passcode header. Students voting never see any counts.

✅ The paper trail

✓
Every vote row stores voterId (Firebase UID), voterEmail, categoryId, nomineeId, and createdAt. Export the full log as CSV from the Audit Log tab at any time.
✓
MongoDB Atlas logs all direct database access under Atlas → Activity Feed. Any tampering outside the app is traceable.
✓
For maximum trust, give a neutral third party (e.g. a faculty adviser) read-only Atlas access so they can independently verify counts after voting closes.
